## Notes

Commentary for Foolshot. These are interpretations of the verbatim text above, not the author's claims unless stated.

- **Setup.** A follow-up live run on ₹1 lakh of real money, with Claude deciding trades and the author approving each order by hand. Zerodha was named as the broker in a reply (spelled "zeordha"). Stops before entry, nothing held overnight, new ideas paper-traded first, and no trade when the rule says the day is a no-trade day — all stated in the posts. Execution moved to a rented Mumbai server with a fixed IP after the IP incident.
- **Reported result.** The author answered "What's the overall pnl?" with "6.5k something" on Day 3. Day 4 reports −3.6k; Day 5 reports −3.7k plus a separate −30k paper-scalping session. The Day 5 post says the account is down ~1.6% over five days. None of this is broker-verified in the captured posts.
- **IP change killed an exit (Day 2, described in the Day 3 post).** Home internet changed IP mid-trade; the broker accepted orders only from one IP, so the bot could not exit; the broker closed the position. This is the same failure class as the archived week's fixed-IP failure, reproduced on the second run. It changes Foolshot's execution setup: pre-register the static IP, run from a fixed-IP host, and keep an out-of-band exit path that does not depend on the agent's session.
- **NSE/SEBI static-IP rule (20 November 2026, after this run).** Notes on Circular 58/2026 are in [`../notes/learning.md`](../notes/learning.md). The requirement that pushed this author onto a Mumbai server is now an exchange requirement for independent API coders: static IP registration, a written undertaking that the trader codes their own algos, and no exchange grievance recourse for losses caused by the algo's logic.
- **Deployment bugs cost real sessions.** A bug shipped the night before Day 5 made the bot think the market was closed for a holiday, and paper trading switched itself off at 09:16 on a normal Friday; the author fixed and restarted. Sizing a session on a fresh deployment is an operational risk, not a strategy risk.
- **Startup and monitoring.** From Day 4 the bot starts itself at 08:50 whether or not the author logs in, and the author's phone is pinged if it is not running. That is a direct answer to the Day 4 loss, where a late login decided the day.
- **The author overrode his own no-trade rule** — "claude even said skip. then i said use the margin" — and the trade lost. A Foolshot rule must not be overridable by a chat instruction; the deterministic gate and the human approval path have to enforce that in code, not in a prompt.
- **Cost floor for new rules.** The author tested a 1–3 minute scalping variant on 20,000 trades of 1-minute data: "zero edge before costs, guaranteed loss after". He then paper-ran it at ₹5 lakh per trade and reported 72 trades in four hours for −30k paper. Any new Foolshot rule should clear the full NSE cost stack before it gets capital.
- **Agent capacity is a dependency.** The author noted Claude limits moving "from 20x to 10x" and that "ai allowances are getting shorter every other day". A 90-day Foolshot run needs a plan/BYOK review and a fallback model path, not a single subscription.
- **Day-label inconsistency.** The 3 November 20:54 post says "tomorrow we gonna trade again", while the 4 November 16:38 post is labelled "day 3" and says Day 1 and Day 2 already happened and two market days were lost to setup issues. This file keeps the author's labels and the X timestamps exactly; readers should not infer session dates from them.
