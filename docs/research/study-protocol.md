# Foolshot research protocol

**Question.** Across a 90-calendar-day study, can a model improve its later decisions and operating reliability by auditing its own predictions, forming theories and testing them with later evidence?

## Trace a learning cycle

| When | AI responsibility | Durable evidence |
|---|---|---|
| Before a position | Write a pass or long decision, cite available observations, explain what would invalidate the hypothesis, set proposed entry, stop and target. | Frozen cutoff, model ID in the cohort manifest, full request, validated result, raw response and latency. |
| During a position | Deterministic code sizes the order, observes later depth and records fills, marks, estimated cost and unresolved exposure. | Intent, risk room, depth tape, position and exit events linked by ID. |
| After a position | Identify what worked, what failed or remains unknown. Supply an evidence-linked check for the next position. | Reflection and its availability time. The next adaptive packet records which prior lessons it actually received. |
| At daily close | Reconcile the synthetic balance, reserve gains, review predictions and execution; solicit owner steering. | Close, attempts, misses, trade outcomes, daily reflection and separate owner notes. |
| Each study week | The AI's “dreaming” review examines accumulated evidence, proposes a competing theory or harness fix and describes how later evidence could reject it. | Weekly proposal, evidence IDs, test and rejection condition. Carry the weekly lesson into later adaptive decisions. |
| On later sessions | Compare adaptive and frozen arms on matched opportunities, including abstentions. | Paired daily returns and weekly differences linked to the prior weekly reflection. |

Run one paired study per client and named model. Both arms receive the same synthetic observations and cost assumptions. Each owns its own ledger, so the effect of earlier decisions can carry forward. The frozen arm receives account state; the adaptive arm also receives prior lessons. This measures the contribution of the feedback workflow. It does not isolate the effect of an individual lesson. For a promising individual hypothesis, freeze a separate control and one changed rule, then test on an unopened interval. The originally planned opening-range comparator is an additional baseline still to implement.

## Before launching the 90-day paper

Freeze the target cohort, session roster, universe, input rights, model identifiers, token/cost logging, simulated fill model, primary metrics, stop rules, intervention categories and out-of-sample dates. The current three-date sample tests software only. Register baseline and candidate versions before opening later data. Preserve null results, all failed variants, holdout inspections, abstentions, outages and unresolved exposures. Distinguish paper and actual broker records throughout.

Primary economic outcome: paired difference in net results after fees, plus separately measured operating spend. Operational outcomes: protection gaps, risk vetoes, unknown acknowledgements, availability and human interventions. Report samples and uncertainty by session or week; trades from one session share market conditions. Daily loss and the fixed capital ceiling govern exposure. Peak drawdown can be described in the results. Record weekly changes in a timeline alongside market conditions and model-provider updates.

## Human and software changes

The AI originates analyses and weekly candidate changes. Puneet can agree, challenge a claim, or steer the next question. Record the exact input, the decision, and which future session may use it. Record rationale as a concise, inspectable thesis with sources. Weekly proposals never confer broker permissions. Production code changes need a separate version, tests, independently checked outcomes, an owner decision and a rollback version. Keep both losing and winning revisions.

## Publication and privacy

Write the eventual paper around methods, paired results, incidents, interventions, negative findings and limitations. Keep a private reproducibility archive with source version, state, evidence timestamps, model I/O, policy, inputs and trial outcomes. Share redacted aggregates and permitted data. Independent reviewers can inspect registered evidence locally. Synthetic paired differences and a single actual brokerage history answer different questions.

## Decision quality alongside money

Each model gives a probability that the final observed bid will exceed the decision-time ask, even on a pass. The evaluator records the outcome and squared probability error (Brier score; lower is better). The current fixture endpoint is the last available quote, recorded at 15:05 IST. Register a uniform forecast horizon for a prospective study. The model also declares which supplied memory IDs influenced its decision. This is a self-report. The saved packet proves what was available. Execution uses a provisional 60-second paper entry lifetime and starts simulated flattening at 15:00 on regular fixture days.

At the next completed study week, the trial reviewer sees the earlier weekly hypothesis, its original rejection criterion, and later matched observations from both arms. The reviewer cites those later event IDs and records a verdict of consistent, weakened or inconclusive, with a competing explanation. An inconclusive verdict is appropriate when the proposed test was never run. That assessment becomes available to later adaptive sessions.

Register both model routes and record each release actually selected or reported. Both arms use the same thinking release for trade decisions. Count operational and strategic calls separately when measuring cost. Use history_with_actor for decision authorship, model release and execution attribution. Explicit CLI selection and provider-reported identity have distinct evidence labels.
